# Planned time, deadlines and the day timeline

B21 extends existing tasks; it does not reinterpret earlier schedules. The legacy Dart `dueDate` and API `due_date` / `scheduled_date` still mean planned start. A separate optional deadline can be a civil date or a zoned instant. Duration is 1–1440 elapsed minutes and can also be an estimate on an unplanned task. These fields survive review, SQLite, account sync, conflict preservation and TaskFlow archive round-trips. Older clients that omit the new API fields do not erase them.

## Behavior

- A planned start can move independently of its deadline. A deadline-only task has no invented start. Explicitly accepted quick-entry phrases such as “submit report by Friday” and “entregar factura antes del viernes” set deadlines; ordinary “on Friday” suggestions retain their planned-date meaning. Undo restores the original text and planning fields. Mixed unsupported intent remains text.
- More details exposes duration and deadline controls. Details show planned time, duration and deadline separately, with an informational notice when the plan ends after the deadline. Date-only deadlines expire at the next local midnight.
- One selected reminder anchor applies per occurrence: planned start (the existing default) or deadline. The task states the choice; device opt-in and reminder lead/time preferences still apply. A deadline-only capture defaults to its deadline. Snooze retains the original occurrence identity through a planned move; changing the anchor instant invalidates an old notification action.
- Repeating deadlines follow the civil-day gap between the first planned date and first deadline. Each later deadline is based on the original occurrence date. Moving one occurrence keeps that deadline; skipping removes its projections and alerts. Editing the whole series start keeps the first deadline and therefore changes the later relative gap; the editor explains this. Device-local repeating wall times retain the existing travel limitation; this is not timezone-bound recurrence.
- Calendar remains the landing screen and its ordinary agenda remains the default. The explicit Day timeline shows planned blocks, deadline points and read-only selected phone events. Calendar also includes overnight block tails and deadline-day entries, deduplicated by original occurrence.
- The timeline uses elapsed geometry between local midnights, including 23/25-hour DST days, overlapping lanes and horizontal scrolling. A colored stripe represents actual duration. A point or short item keeps a larger labeled tap target; the view explains this. At most 200 timed items render in the grid with a visible limit notice; the agenda remains available for all tasks. Device-calendar access/lifecycle checks also apply here.
