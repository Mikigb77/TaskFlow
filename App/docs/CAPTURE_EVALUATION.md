Capture evaluation and local diagnostics
========================================

`Backend/core/evaluation/capture_cases.json` contains synthetic English and Spanish examples with fixed reference dates and IANA zones. The command never reads users, tasks, recordings or production transcripts. Cases cover Inbox/date-only tasks, explicit and ambiguous hours, corrections, independent batches, preparation notes, priority, midnight, local reference dates and daylight-saving gaps/folds.

Run `docker compose exec -T api python manage.py evaluate_capture` to list the case count without a provider call. Add `--live --output /tmp/capture-evaluation.json` to call the configured text model and write its synthetic outputs and scores. `--case <id>` selects a case. Live runs consume provider quota; a 429 stops the run and leaves the remaining cases unmeasured. Any failed or unmeasured case exits nonzero.

Scoring matches each case's distinct title concepts without requiring task order, then checks annotated schedule, priority, recurrence, questions and note details. A replacement task counts as an omission and an unwanted addition. This is a regression set, not a calibrated accuracy estimate: title/notes synonyms can need human review, and passing title keywords does not establish general language quality. Latency includes the bounded retry; provider failures are excluded from successful-response percentiles and reported separately. These are text extraction measurements, not speech recognition or end-to-end user timings.

Settings → Capture diagnostics stores the latest 1,000 local enum events with numeric durations/counts only. It includes startup, permission denials, typed input, first on-device words, listening, online audio transcription, extraction, review, correction dialogs, durable local saves, retries and retained exits. Typed/native text does not add zero-duration audio transcription samples. Counts include repeat visits and cannot be interpreted as a conversion rate. Leaving a saved draft for later is distinct from failure or explicit discard. Review time includes thinking time; correction time measures open editing dialogs, including cancellation. Save latency ends at the local transaction before cloud sync. No titles, transcripts, audio, account identifiers or arbitrary tags enter these diagnostics.

Verification: 41 backend tests pass, including scorer regressions, no-network default and quota interruption reporting. All 19 focused Flutter capture/review/native-speech tests pass, including typed input's exclusion from audio transcription timings. Static analysis is clean. The live provider report is recorded separately from these deterministic checks; service failures must not be described as extraction accuracy results.
