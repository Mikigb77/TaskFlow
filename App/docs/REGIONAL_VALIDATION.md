# Language and regional preferences

B18 adds Settings → Language & region with device defaults and overrides for UI language (English/Spanish), 12/24-hour time, Sunday/Monday/Saturday week start, and the timezone used to interpret new captures. Regional preferences are device-local SQLite data; switching accounts does not reset them. Writes are serialized, startup restoration cannot overwrite a newer choice, and a failed write restores the last saved preference with a visible error.

Calendar, recurrence weekday controls, date/time pickers and task labels use the same regional settings. Android/iOS system clock choices take precedence over locale defaults, including a UK device explicitly set to 12-hour time. Returning from system settings refreshes the clock choice. Switching language keeps navigation and editor values. Imported dates before 2000 or after 2101 remain editable.

New captures use an explicit IANA timezone override, otherwise the device timezone, with a visible account/UTC fallback when device lookup fails. Unfinished captures retain their original reference time and timezone. Existing task instants, date-only values, recurrence and completion data are not rewritten. Timezone validation preserves the reminder service's selected timezone. New account registration without a supplied timezone now defaults to UTC; migration 0007 does not change existing profiles. Task display still follows the device timezone; this is not a migration to timezone-bound recurring series.

Localization uses Flutter's generated ARB resources, `flutter_localizations`, and locale-aware `intl` formats. English and Spanish resources cover the main navigation, agenda/Inbox, settings, task editor/details, capture/review, checklists and shared reminder/recurrence controls. Account, list management, shared-list membership, notification management, OS notification copy and archive import/export now use the same resources, including validation, confirmation, role/color labels and import warnings. Capture recovery also localizes recognized connection, service, permission and storage failures. Translation rollout remains incremental: unknown server/platform-provided errors and some detailed action messages still use English. User content is never translated. New translated text belongs in `lib/l10n/app_en.arb` and `app_es.arb`; regenerate with `flutter gen-l10n` (also run by `flutter pub get`). See [Flutter internationalization](https://docs.flutter.dev/ui/internationalization).

OS notifications and concurrency, 23 September 2026:

- Added 11 bilingual messages (690 matching message keys). Due/advance/deadline/date-only alerts, check-ins, snoozes, channel names and Complete/Snooze labels read the same saved regional preference as the UI, including in a background engine. Language changes refresh pending copy without changing task content, due times, notification IDs or retained snooze choices. Delivered alerts keep their action token. iOS categories are registered for both languages while retaining the legacy category; iOS delivery has not been tested.
- The first native action test exposed SQLite contention between separate foreground/background connections. Enabling Android WAL permits reads during a writer transaction. Competing writes also need to yield: Android uses a zero busy timeout with a bounded, asynchronous retry of individual statements rejected with SQLITE_BUSY. Transaction callbacks and batches are not replayed; extended busy-snapshot errors and unrelated failures are not retried. The small adapter uses sqflite's internal factory hook, so dependency upgrades must rerun the native concurrency suite. Other platforms retain their previous connection behavior. See [sqflite WAL setup](https://raw.githubusercontent.com/tekartik/sqflite/master/sqflite/doc/dev_tips.md) and [its isolate guidance](https://raw.githubusercontent.com/tekartik/sqflite/master/sqflite/doc/usage_recommendations.md).
- A competing reminder refresh now waits for the existing lease, then reads a new task snapshot. It reports a bounded failure if the worker remains busy, allowing WorkManager to retry. It no longer silently drops a refresh for an edit made after the other worker's snapshot. Unit tests exercise this race and verify that a timed-out caller cannot steal the lease.
- All 190 Flutter tests pass and analysis is clean. The Android suite passes a read held against an open writer transaction, two competing transaction callbacks (called once each), rollback, and ten additional simultaneous transaction/autocommit rounds. The real notification fixture changes English to Spanish through Settings, retains IDs/schedules/task content and channel behavior, then receives both alerts. The host tapped the actual observed Completar and Posponer 10 min buttons. SQLite recorded completion and a ten-minute snooze with Spanish follow-up copy and unchanged task due time.
