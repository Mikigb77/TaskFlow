### Regressions
**R1A-1 · Severity 2 · A task moved «a mañana» lands reading «Sin fecha»**
- Where: `App/lib/widgets/task_tile.dart:48` (`_dateLine`), on Calendar's day list after a voice move of a task that has only a deadline. Seen in `App/build/ux/commands/applied.bulk-applied.es.light.1x.png`: the row says «🕒 Sin fecha   Vence vie, 23 de oct», directly above «4 tareas movidas al vie, 23 de oct».
- The moment: «Le he dicho que la pase a mañana, me dice “movida al viernes”… ¿y pone “Sin fecha”? ¿Se ha guardado o no?»
- What happens: D1 now leaves a moved deadline-only task with no planned day (correctly). The row logic is not new: a row with no `displayDate` prints `noDate` whenever `showUndated` is set. But before this change, a voice move never produced such a row, and now every voice move of a deadline-only task ends on one. That ending is the moment the user remembers (peak–end).
- Why it fails: the row contradicts the confirmation beside it (Nielsen: consistency, visibility of system status). The first words of the line are «Sin fecha», so a user who scans the row reads the wrong thing first (Nielsen 2006 on scanning: front-load the key information).
- Fix: subtract. A row whose task has a deadline doesn't say «Sin fecha»; its «Vence …» line already says when it is due: `if (date == null) return showUndated && task.deadline == null ? context.l10n.noDate : null;`. No new copy. Update the applied.bulk-applied description: «… reading only «Vence <tomorrow>»».
- Verify: re-render commands/applied.bulk-applied; a widget test on Calendar where a deadline-only row shows «Vence …» and no `noDate`, in ES. A deadline-only row on Tareas should also lose «Sin fecha» (check `task_rows_test.dart` for a test that pins it there).
- Evidence: seen in a current render; the cause is verified in code.

### Not regressions (checked)
- A time only («a las 18:00») on a deadline-only task reads «Cambiar fecha» and then «Movida al <its day>», the same words a planned task gets for a change of time only (`_onlyMoved`). It's consistent, and there's no chip (`moves` needs a `date` or `shift_days`, capture_command_cards.dart:1407).
- `date` together with an explicit `time: null` on a deadline-only task drops the deadline's time, the same way the planned-day block treats a planned task. That's the rule the brief asked for.
- At 2× the «→» wraps onto its own line in cards.change-deadline-only.es.light.2x.png. That's P233's `moveLine` layout, the same on every move card, and wasn't changed here.
