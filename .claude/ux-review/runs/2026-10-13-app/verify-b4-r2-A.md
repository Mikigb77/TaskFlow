## UX verify — 2026-10-13-app, batch 4 round 2, area A (P67, P68, P69) — 2026-10-14
**Verdict:** Ship. All 7 findings are fixed in code, and the tester's acceptance tests pass. No regressions caused by these changes. One Calendar observation goes to U5, not here.
**Evidence base:** code read (`git diff HEAD` plus targeted reads), the tester's results, and the current render `App/build/capture-listening-es-2x.png` (02:37, newer than the code at 02:11–02:17; unchanged listening state, looks right). No current render shows the failed pair, the typing hint, the time question or the timeline landing, so those rest on code and tests.

### Results
- **UX-103 · fixed (device check open).** Copy: `captureNoSpeech` and `captureSpeechStopped` in EN/ES/CA are the brief's exact values, and neither names a button (`app_es.arb:890-891`, `app_ca.arb:698-699`, `app_en.arb:1181-1182`). No catalog contains `Toca Seguir`. Behaviour: after a 422 on saved audio with no words, `_dropSilent` discards the record, and `store.discard` also removes the audio (`capture_store.dart:362-384`). `_session` becomes null, `_failed` false, and the noSpeech banner stays (`voice_task_screen.dart:1077-1090`, `1120-1129`). With `_session` null, `_hasInput` is false, so `waiting` shows `Empezar a hablar` (`:1478`, `:1493-1498`), and the keyboard icon returns (`showType: !recorded`). A capture reopened from the pending list gets the same drop (`:462-468`). Pendientes opens with `startListening: false` (`captures_screen.dart:59-61`), so it doesn't start listening by itself. Typed 422s show `captureFailed` through `_problemFor(heard: false)` (`:1111-1116`), and `capture_problem.dart`'s mapping is unchanged. If the drop fails, the user keeps `Reintentar`, which is the safe fallback. Open device checks: real silence, and Pendientes showing nothing new.
- **UX-467 · fixed (device check open).** The 8 s timer calls `_announce(context.l10n.captureSlow)` right after `_slow = true`, guarded by `superseded()` (`voice_task_screen.dart:1032-1036`). The test asserts one announcement. Open device check: TalkBack actually speaks it.
- **UX-468 · fixed.** The hint is `_kind == 'note' ? noteHint : _voice ? examplePlan : exampleTask` (`voice_task_screen.dart:1541-1545`), so it follows the `local: !_voice` flag (`:1055`). `exampleTask` is in all three catalogs, with a description in `app_en.arb:387-389`. Catalan uses `Metge divendres a les 17:00`, the fallback the brief allowed: the parser reads `17 h` but leaves `h` in the title. The parser test covers each catalog value.
- **UX-469 · fixed (device check open).** `stack: failed && saveAsWritten` (`voice_task_screen.dart:1661`). `_controls` puts every primary button on its own row at full width when `large || stack` (`:1736-1756`). Order: `Reintentar` (tonal) above `Guardar tal cual` (filled), so the filled button sits lower, in the thumb zone. Listening, paused and waiting layouts are unchanged (`stack` defaults to false). Open device check: each Catalan label fits on one line at 360 dp.
- **UX-470 · fixed.** ES `Dictar una tarea es parte de TaskFlow Pro. Puedes escribirla aquí.` (`app_es.arb:1164`); CA `Dictar una tasca forma part de TaskFlow Pro. La pots escriure aquí.` (`app_ca.arb:858`).
- **UX-465 · fixed.** `capture_review_editor.dart:151-156` shows `question.question.isEmpty ? l.captureWhatTime : question.question` in the same style. `captureWhatTime` is in all three catalogs, with a description in `app_en.arb:18-20`. The stale "chips alone" comment is gone, and `local_capture.dart:106` keeps `question: ''`. The only empty-question source is the phone's AM/PM question, so the generic fallback can't show on another field today.
- **UX-466 · fixed (device check open).** The timeline passes `TaskActions(day: _day, page: this)`, and its `ref.listen` acts only on `identical(focus.page, this)` (`day_timeline_screen.dart` `_land`, the build listener, the `bottomNavigationBar`). Calendar ignores page-scoped focus (`calendar_screen.dart:198-201`).
  - **Same day:** the timeline waits until the task appears in `unblocked` or in the timed layout, then lights it: `LandedTaskTile` for untimed tasks, and a `lit` tween on `_TimelineBlock` (primaryContainer, 0 ms when animations are off). It scrolls the row in with `ensureVisible` at alignment .15 and fades the light after 1500 ms.
  - **Other day or no date:** `popUntil(isFirst)`, then `CalendarFocus(day, ids, showCalendar: true)` in a microtask, so Calendar selects the day or the no-date row and lights the task.
  - **Note for U5, not a regression:** the tester measured, at 390×844, Calendar's lit `Bandeja · 1` row (y 541–589) almost entirely under the `Tarea guardada en la bandeja de entrada` message (top 551). Calendar can't scroll it clear because its content is short. The same thing happens when saving a no-date task from the pending list, so P69 didn't cause it. It does contradict U5's "Calendar lands (verified)". Suggested fix, for the U5 owner: give Calendar's scroll content a bottom inset of at least the save message's height + 8 dp while a landing is active, so `ensureVisible` can lift the row clear. This is the same clearance idea UX-460 proposes for Tareas.

### Regressions
None found in `voice_task_screen.dart`, `capture_review_editor.dart`, `day_timeline_screen.dart` or the three catalogs. Paths checked:
- noSpeech drop then `Cancelar`: closes with nothing to ask about.
- noSpeech drop then `Empezar a hablar`: `_startRecording` clears `_error` (`:716-720`), and a new session is created.
- Typing with Pro: still shows `examplePlan`.
- Notes: still show `noteHint`.
- A failed pair on a wide screen: now always stacked, as the brief asks.
- Timeline landing with kept drafts (`remaining > 0`): sets no focus, and the sheet stays.
- The timeline is reached only from Calendar (`calendar_screen.dart:186`), so `showCalendar: true` can't switch tabs unexpectedly.
- After the fade, the landed row's resting colour matches its neighbours (`TaskTile` defaults to `colors.surface`).
