Notes, not regressions:
- The accepted known limit stands: on a gone project's page, each `taskProvider` change rebuilds `taskListsProvider`, so for one local read the bottom bar and empty-state sentence flip to `Añadir tarea` / `Añade una tarea a este proyecto…` and back. Rare page; the plan accepted it.
- Other ways into a project page were checked: Proyectos (:337), group page (`groups_screen.dart:715`) and invitation accept (`invitation_cards.dart:351`). Both accept paths await `refreshAfterInvitation`, which invalidates `taskListsProvider` before `showJoined`, so a just-joined project normally sees the reloading state, like UX-626. Only if that refresh fails (the dialog swallows the error at :215-217) and the project isn't stored locally does the joined page show `Este proyecto es de solo lectura` until the next sync. That is safer than round 2's `Añadir tarea`, which saved outside the project, and it matches the behaviour before P114. Worth watching on the two-account device check.
