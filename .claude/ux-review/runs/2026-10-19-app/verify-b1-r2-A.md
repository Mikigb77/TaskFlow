### Notes (not regressions; candidates for a later pass)
- **A task that goes into an existing project is announced as a bare verb.** A task plus an existing-project card (`commands/cards.project-exists`) is 2 cards. Because the project already exists, `adding` is false, so rule (b) announces only the button, «Añadir tarea». The person hears an instruction, not what was understood: no title and no date. This was silent before the change, so it's an improvement, not a regression. Suggested fix, with no new strings: when there's exactly one pending task and every other card is a project card, announce the task as in the one-task case («{title}, {taskDayLine}»), then the question. For example, «Repasar fracciones, Sin fecha».
- **The button-label rule drops the task while its question is open.** In a mixed result whose only task has an AM/PM question open, the button reads «Cambiar y eliminar», so the announcement doesn't mention the task to add, only the question that follows. This follows the brief's rule (the label as shown). Prefixing the pending task's title would close the gap.
- **«Ver lo que dije» is cut at the footer's edge.** In `commands/cards.project-new.es.light.2x`, the row is partly hidden at the bottom of the scroll, so AUDIT measures only 312 × 41 dp of it. That's the scroll position, not the row's size: it is 56 dp once scrolled. The extra 4 dp after compact cards moves it slightly further down. No action needed.
