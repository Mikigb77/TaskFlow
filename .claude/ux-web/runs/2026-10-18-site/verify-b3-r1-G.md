## Regressions

**R1G-1 · Severity 1 · At 200 % text on a phone, the sticky header takes two rows**
- Where: `src/styles/global.css:258-283` (`.site-header { position: sticky }`, `.header-inner { flex-wrap: wrap }`, `.brand { font-size: 1.4375rem }`); renders `home.en.mobile-text200.light.fold.png`, `home.es.mobile-text200.light.fold.png`, `privacy.es.mobile-text200.light.fold.png`.
- The moment: the newcomer with a larger browser text size scrolls and a fifth of the screen stays covered by the logo and the Menu button: «¿Por qué no se va esto?»
- What happens: now that text grows (the fix), the wordmark grows to 46 px and pushes "Menu" onto a second row; the header measures about 127 CSS px of a 664 px viewport (19 %) and stays stuck while scrolling. Before the change it couldn't grow at all, so this is a side effect, not a step back in readability.
- Why it fails: WCAG 1.4.10's Understanding notes on sticky headers at high zoom; lens J (sticky elements never cover content). Not a WCAG failure: content is reachable.
- Fix: the wordmark is a logotype, which WCAG 1.4.4 exempts from resizing, so cap it: `.brand { font-size: min(1.4375rem, 28px); }`. At 390 px with text at 200 % the logo (≈ 165 px) and the Menu button (≈ 147 px) then fit one row in the 350 px container. Leave the Menu label growing.
- Verify: `home.*.mobile-text200.light.fold.png` shows logo and Menu on one row; Playwright at 390 × 664 with the default font at 32 px: `.site-header` height ≤ 90 px. At 320 px a wrap is still acceptable.
- Evidence: seen in current renders; height measured from the render (border at y ≈ 382 device px / 3); the effect of Android's own font-size setting on Chrome needs a device.

No other regressions in global.css's pages: the removed `.prose-page`, `.button-small` and footer-brand rules have no remaining users (`grep` of `src/`); `.eyebrow` is used only by `LegalPage.tsx:116` and reads fine at 12 px uppercase (`delete-account.ca.mobile-w320.light.fold.png`); the desktop text200 renders switch to the Menu button at the 64em breakpoint and fit (`home.ca.desktop-text200.light.fold.png`). Without JavaScript the hidden theme toggle leaves a 44 px empty gap at the desktop header's right end (`home-nojs.en.desktop.dark.fold.png`); that is the brief's "no layout shift" and not a finding.
